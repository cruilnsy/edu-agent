Exam grading agent graph

Nine nodes run in order, with no conditional edges. Unlike the resume agent, this graph has a MemorySaver checkpointer and pauses at step ⑦ with interrupt(): the AI only produces a pre-review, and the graph resumes and publishes to the student after a teacher confirms.

API lifecycle

Grading runs in two parts: on submit, a background task runs ① to ⑦ and pauses; on confirm, ⑧ and ⑨ run inside the request. From backend/api/v1/exam.py. Every query is scoped to the caller's tenant.

Three grading tracks

The tracks run in parallel and do not affect each other. A question is flagged needs_review for the teacher when confidence is below 0.7 or the answer asks the grader for marks.

Student answers are wrapped in <student_answer> tags, and the prompts tell the model to grade any instructions inside them as content, not follow them.

Nodes

① parse_word
Runs python-docx in a thread pool. Finds "Question N" headers and takes the text after "Answer:"; fenced code keeps its indentation. A parse failure returns an empty list and the graph continues.
② load_questions_meta
The DB questions of the exam (in the tenant) are the source of truth. Merges the student's answers by question number and adds type, answer key, scoring points in rubric order, full score and tag.
③ run_three_tracks
Splits the questions by type and grades the three groups in parallel. If a whole track raises, each of its questions gets a 0-point fallback result flagged for review, so no question is dropped.
④ aggregate_results
Merges the tracks, computes total, full score, rate and review count, and builds the teacher's pre_review_summary. Sets fallback_used if any result is a fallback.
⑤ analyze_weak_points
Groups lost points by knowledge tag (the count covers every question with the tag) and asks the LLM for advice and a summary. Skips the LLM when every answer is right.
⑥ notify_teacher
Sets the submission to pending_review. Only updates the status and logs; no real notification is sent yet.
⑦ teacher_review
Calls interrupt() to pause the graph. When resumed, its return value is the teacher's decision.
⑧ apply_teacher_decision
Copies the AI scores as final scores. On modify, replaces scores and comments by question_id, clamped to 0..full score; modifications are ignored on approve. The branch is inside the node, not a conditional edge.
⑨ publish_results
Replaces each question's row in exam_reviews, then sets the submission to published and saves the weak points.

Known limit: the paused state lives in process memory, so a backend restart loses every grading that is waiting for a teacher. Production should use AsyncPostgresSaver.
